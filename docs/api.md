# API reference

Public routes start with `/api`. Unsafe requests must include an `Origin` equal to `PUBLIC_ORIGIN`. JSON mutations use `Content-Type: application/json`. Session cookies are issued by login.

## Authentication

| Route | Request and response |
| --- | --- |
| `POST /auth/admin/login` | `{ email, password }`. Accepts an active HR account. Returns 200 with the actor profile and a session cookie. |
| `POST /auth/karyawan/login` | Same body, accepts an active employee. Wrong-role credentials return 401. A correctly authenticated inactive employee receives 403 and the account-status message. |
| `GET /auth/me` | Returns the current active actor profile. Invalid, revoked, stale-version, or expired sessions return 401. |
| `POST /auth/logout` | Revokes a valid session, clears the cookie, and returns 204. |

## HR account management

| Route | Request and response |
| --- | --- |
| `GET /employees?page=1&active=true` | HR only. 50 items per page and a `hasNext` flag. Omit `active` to include inactive and legacy pending accounts. |
| `GET /employees/:id` | HR only. Employee details, excluding credential hashes. |
| `POST /employees` | HR only. `{ employeeCode, displayName, email, password }`. Returns 201 with `{ id }`. |
| `PATCH /employees/:id` | HR only. `{ displayName, email }`. An existing legacy pending employee can also receive `initialPassword`. Returns updated employee details. |
| `DELETE /employees/:id` | HR only. Soft-deactivates an employee and returns 204. Repeating the request preserves the inactive state. |
| `POST /employees/:id/reactivate` | HR only. Reactivates an employee and returns 204. Repeating the request preserves the active state. |
| `POST /admins` | HR only. `{ displayName, email, password }`. Creates another admin with the same HR permissions and returns 201 with `{ id }`. |

Names contain 2–100 characters. Employee codes contain 1–24 characters and normalize to uppercase. Emails normalize to lowercase and are unique. Initial passwords contain 12–128 characters. Login accepts 8–128 characters to support the optional local demo credential. Unknown JSON fields are rejected. Duplicate email or employee code returns 409.

## Attendance

| Route | Access and behavior |
| --- | --- |
| `GET /attendance/today` | Employee only. Returns `{ date, attendance }`, with null attendance when nothing is recorded today. |
| `POST /attendance` | Employee only. Multipart form with exactly one `photo`. Returns 201 with `id`, `employeeId`, `date`, and `submittedAt`. Identity and time come from the server. |
| `GET /attendance?from=2026-11-05&to=2026-11-05&employeeId=2&page=1` | HR only. Inclusive date range up to 31 days, optional employee ID, and 50 items per page. Defaults to today. Returns `items` and `hasNext`. |
| `GET /attendance/:id/evidence` | HR or the owning employee. Returns private image bytes. Another employee receives 404. |

HR has read-only attendance access. Missing or damaged photos return 400, oversized photos return 413, supported image decoding with an unsupported format returns 415, and a duplicate daily record returns 409.

## Private service and health

The private service listens on loopback at port 3001. Its routes mirror attendance operations under `/internal/attendance`. Requests need `x-service-key`, `x-actor-id`, and `x-actor-role`, generated by the public API.

Public readiness is `GET http://127.0.0.1:3000/api/health`. Private readiness is `GET http://127.0.0.1:3001/internal/health`. Both return `{ status: "ready" }` when their database query succeeds.

Errors use NestJS response bodies with `message`, `statusCode`, and usually `error`. Authentication and permission failures use 401 and 403. Missing records use 404. Attendance dependency failures use 502, 503, or 504 as appropriate.
